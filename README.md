앱의 세 탭을 `오늘 / 계획 / 나의 변화`로 재편했습니다. 오늘 화면은 `fixtures/sample-plan.json`의 예시 세션과 식사 체크를 보여주고, 계획 화면은 같은 파일의 4주 목록·진행도·변경 사유를 표시합니다. 기존 차트 7종은 모두 나의 변화로 이동했습니다. 자세한 구조는 [처방 중심 정보 구조](정보구조_처방중심_개편.md)를 참고하세요.

## 2026-09-13 콘텐츠 정책 변경

본문·이미지·영상 크롤링 계획은 전면 취소했습니다. 공식 API 링크 카드와 운영 승인 기능을 추가했습니다. 실행·인증 설정은 [콘텐츠 링크 카드 운영](콘텐츠_링크카드_운영.md)을 참고하세요. 사용자 목록은 서버에서 `approved` 카드만 반환하며 운동 지시문은 별도 필드로 관리합니다. 아래 이전 기록의 수집 계획보다 이 변경이 우선합니다.

**실행:** `BodyFlow.html`을 Chrome 또는 Edge에서 여세요. 별도 설치 없이 실행됩니다.

- 실제 Lieflat 템플릿 7종, 라이트/다크 테마, 기간 선택·값 탐색·재생
- 날짜별 체중·식단·운동 기록 입력/수정, 브라우저 저장, JSON 백업/복원
- 예시 데이터와 내 기록 분리. 러닝·페이스·레시피는 현재 예시 데이터
- Figma 32종 × 2테마 = 64개 상세 화면. 실행 앱은 차트·기록 중심의 일부 기능 구현

최신 범위와 남은 작업은 [진행현황_구현범위_보완과제.md](진행현황_구현범위_보완과제.md)를 확인하세요.

## 파일 안내

| 파일/폴더 | 용도 |
|---|---|
| BodyFlow.html | 독립 실행 앱 |
| app/ | HTML·CSS·JavaScript 분리 소스 |
| assets/lieflat/ | 실제 템플릿 SVG 및 Figma용 벡터 |
| reference/lieflat-charts/ | 사용한 원본 파일과 라이선스 |
| provenance.json | 커밋·템플릿 추출 출처 |
| qa/ | 브라우저/Figma 검수 결과와 화면 캡처 |
| tools/ | 빌드, 테스트, 네이버 연결, 전달 폴더 복사 스크립트 |
| design-manifest.json | 클라우드 Figma 화면·차트 노드 목록 |

기록은 브라우저에만 저장됩니다. 파일 위치나 브라우저를 바꾸기 전에 JSON으로 백업하세요. API 인증키는 포함하지 않습니다. 원본 차트의 비상업 라이선스와 상업 배포 전 검토 사항은 진행 보고서를 참고하세요.

## 이전 Figma 납품 기록

아래는 이전 디자인 단계의 기록입니다. ‘실제 연결되지 않은 기능’은 당시 Figma 기준이며, 현재 로컬 앱의 입력·저장·차트 동작 범위는 위 안내와 최신 보고서를 따릅니다. 기존 직접 작성 SVG는 이력 보관용이고 현재 차트는 실제 Lieflat 템플릿으로 교체했습니다.

# BodyFlow 상세 화면 프로토타입

[Figma 디자인 열기](https://www.figma.com/design/HgoIa0utwpiSp4pQlUPmTL?node-id=56-2)

[라이트 앱 시연](https://www.figma.com/proto/HgoIa0utwpiSp4pQlUPmTL?node-id=56-2&page-id=55-2&starting-point-node-id=56-2&scaling=scale-down)

[다크 앱 시연](https://www.figma.com/proto/HgoIa0utwpiSp4pQlUPmTL?node-id=63-127&page-id=55-2&starting-point-node-id=63-127&scaling=scale-down)

`Detail Flows · 2026.09` 페이지에 32종 화면을 라이트/다크로 각각 구성했습니다. 긴 화면은 프로토타입에서 세로로 스크롤합니다. 기존 Screens 페이지의 두 홈에도 새 상세 흐름으로 이동하는 버튼을 추가했습니다.

## 포함 범위

- 식단, 영양 분석, 메뉴 탐색, 네이버 원문 검색, 재료 기반 레시피 제안 상태
- 자체 레시피 3종, 생성 이미지 3종, 분량·재료·알레르기·조리 안내
- 식사 기록, 메뉴별 완료 화면, 장보기, 저장 오류·빈 데이터 상태
- 주간 리포트, 체중, 근력·유산소 비교, 운동 컨디션·루틴·동작, 러닝 계획·결과
- 콘텐츠 상세, 설정, 두 테마 전환, 큰 글씨 모드
- 7개 차트 유형을 두 테마에 적용한 14개 벡터 차트

## 검증

- 64개 화면, 250개 이동 동작을 검사했습니다. 안내 보드의 추가 진입 버튼은 이 숫자에서 제외했습니다.
- 홈에서 64개 화면 모두 도달 가능. 목적지 누락·동작 없는 버튼 0개.
- 다크 테마에서 의도하지 않은 라이트 화면 이동 0개. 설정의 명시적 라이트 전환만 예외입니다.
- 내부 자동 레이아웃 컨테이너의 범위 초과·요소 겹침 0개. 화면 자체는 의도적으로 세로 스크롤됩니다.
- 라이트/다크 대표 화면, 그래프, 상세 페이지 말미, 큰 글씨 모드를 이미지로 확인했습니다.
- 차트 평균·합계·구성비 산술 검증 통과.
- 네이버 연결 스크립트의 모의 응답 기반 테스트 4개 통과. 실제 API 인증 테스트는 미실행.

## 실제 연결되지 않은 기능

Figma 클릭형 시연입니다. 자유 텍스트 입력, 서버 저장, 사진 분석, GPS, 실제 타이머, 실시간 AI 레시피 생성, 자동 콘텐츠 갱신은 구현된 앱 기능이 아닙니다. 메뉴·인분·루틴 값은 예시 상태를 사용합니다.

네이버 직접 수집은 접근 오류로 완료하지 못했습니다. `tools/naver_recipe_search.py`는 공식 검색 API의 제목·작성자·날짜·원문 링크를 조회할 서버용 연결 코드입니다. NAVER_CLIENT_ID와 NAVER_CLIENT_SECRET이 있어야 실호출할 수 있습니다. 블로그 본문과 사진을 복제하지 않습니다.

Adobe 초기화 오류로 대체 이미지 생성 도구를 사용했습니다. 상세 근거·수치·이미지 제작 기록은 [CONTENT_SOURCES.md](CONTENT_SOURCES.md)에 있습니다.

## 파일

- `design-manifest.json`: 각 화면의 실제 Figma 노드 ID
- `screen-content.json`: 기본 화면 문구와 이동 구조
- `assets/`: 생성한 음식 이미지 3종과 직접 작성한 차트 SVG 7종
- `tools/naver_recipe_search.py`: 공식 API 연결 스크립트
- `tools/test_naver_recipe_search.py`: 연결 코드 계약 검증

네이버 스크립트 사용 예:

```text
python tools/naver_recipe_search.py "두부 다이어트 레시피" --limit 10 --output results/recipes.json
python -m unittest discover -s tools -p "test_*.py" -v
```

API 인증 정보는 서버 환경변수로 설정하고 Figma·앱 프런트엔드·버전 관리에 넣지 않습니다.
